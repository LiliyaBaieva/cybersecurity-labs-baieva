# Програма симетричного шифрування email-повідомлень

##   Загальні положення

**Призначення програми**

Програма призначена для надання користувачам можливості конфіденційного обміну текстовими повідомленнями шляхом використання криптографічно стійкого симетричного алгоритму шифрування (AES-256-GCM). Основною метою є забезпечення простоти використання для отримувача, який повинен мати лише один Секретний Ключ для розшифрування.

**Вимоги до реалізації**

Програма має бути реалізована мовою програмування Python з використанням бібліотеки cryptography для забезпечення високої криптографічної надійності.

**Вимоги до оточення (Залежності)**

Для коректної роботи програми користувачу необхідно встановити бібліотеку cryptography.

Інструкція з встановлення:

 ```-- pip install cryptography```


Виконання програми без встановленої бібліотеки призведе до помилки імпорту.

## Функціональні вимоги

**Алгоритм шифрування**

* **Метод**: Симетричне автентифіковане шифрування.

* **Алгоритм**: Advanced Encryption Standard (AES) з довжиною ключа 256 біт.

* **Режим роботи**: Galois/Counter Mode (GCM), що забезпечує конфіденційність та автентифікацію (перевірку цілісності) даних.

**Генерація Секретного Ключа (Base64-маски)**

1. Ключ, необхідний для розшифрування, повинен бути Base64-кодованою маскою (Base64-mask), щоб приховати відкриті компоненти, з яких він був виведений.

2. Компоненти Секрету: Введені користувачем Email Відправника та Секретний Пароль.

3. Формування Секрету: Секретний рядок формується як: Email_Відправника:Пароль.

4. Ключ-Маска: Для відображення користувачеві цей секретний рядок кодується в Base64-рядок (наприклад, bGkQbS5jb206MTk4Nw==), який і слугує Спільним Секретним Ключем для отримувача.

**Генерація Ключа AES (PBKDF2)**

Фактичний 256-бітний ключ для алгоритму AES-GCM повинен бути виведений з відкритого Секретного Рядка (Email_Відправника:Пароль) за допомогою функції похідної ключа (Key Derivation Function).

* ***Функція***: PBKDF2HMAC (Password-Based Key Derivation Function 2)

* ***Хеш-алгоритм:*** SHA256.

* ***Ітерації***: Мінімум 100,000 ітерацій для захисту від атак перебору (brute-force).

* ***Сіль (Salt)***: Унікальна криптографічна сіль (16 байт) повинна генеруватися для кожного нового шифрування та зберігатися разом із зашифрованими даними.

## Сценарії використання (Пункти меню)

### Режим Шифрування (Відправник)

* **Введення даних**: Запит: Email Відправника, Секретний Пароль, Текст повідомлення.

* **Процес**: Генерується унікальна сіль, виводиться AES-ключ через PBKDF2, повідомлення шифрується (AES-256-GCM).

* **Збереження**: Зашифровані дані (сіль + IV + шифротекст + GCM-тег) кодуються в Base64 та автоматично зберігаються у файл.

* **Іменування файлу**: Файл повинен мати назву message.enc. Якщо файл існує, програма має автоматично створити наступний вільний файл (message1.enc, message2.enc, і т.д.).

* **Виведення**: Користувачеві виводиться Base64-маска Секретного Ключа, яку він має передати отримувачу захищеним способом.

### Режим Розшифрування (Отримувач)

* **Введення даних**: Запит: Base64-маска Секретного Ключа, Назва файлу (.enc).

* **Процес**: Base64-маска декодується, щоб отримати рядок Email_Відправника:Пароль. Цей рядок використовується для генерації AES-ключа (PBKDF2) з використанням солі, взятої із зашифрованих даних.

* **Перевірка**: Виконується розшифрування та автентифікація (перевірка GCM-тегу).

* **Виведення**: У разі успіху виводиться оригінальне повідомлення. У разі невідповідності ключа або пошкодження даних виводиться помилка криптографії.

## Вимоги до інтерфейсу та взаємодії

### Інтерфейс

**Меню**: Програма повинна мати просте текстове меню з трьома основними пунктами: "1. Зашифрувати", "2. Розшифрувати", "3. Вийти".

**Підказки**: Усі запити до користувача повинні бути зрозумілими та чітко вказувати, які дані очікуються (наприклад, "Введіть Спільний Секретний Ключ (Base64-рядок)").

### Обробка помилок

Програма повинна коректно обробляти помилки файлового вводу/виводу (FileNotFoundError, IOError).

Програма повинна чітко повідомляти про криптографічні помилки (невідповідність GCM-тегу, некоректний ключ).

## Вимоги до даних та безпеки

  ### Формат зашифрованих даних

Зашифрований файл .enc повинен містити Base64-кодований рядок, який у собі містить:

~~~
Base64(Salt + IV + Ciphertext + Authentication Tag)
~~~

### Секретність Ключа

Ключ-маска (Base64-рядок) є єдиним елементом, необхідним отримувачу. Його має бути передано поза системою шифрування (наприклад, через захищений месенджер або особисто). Програма не несе відповідальності за безпеку передачі цього ключа.
